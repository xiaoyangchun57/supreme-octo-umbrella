# 代码变更验证规范 - 产品需求文档

## Overview
- **Summary**: 建立一套代码变更验证流程，确保在修改数据处理或核心逻辑代码时，必须与已验证的原始VB源代码进行对比验证，避免引入新的问题。
- **Purpose**: 保障代码质量，确保修改后的代码行为与原始代码一致，减少回归问题。
- **Target Users**: 开发人员、维护人员

## Goals
- 建立代码变更前必须对比源代码的规范流程
- 确保修改后的代码逻辑与原始代码行为一致
- 提供明确的验证检查点和文档记录要求
- 降低代码修改引入bug的风险

## Non-Goals (Out of Scope)
- 不涉及代码版本控制流程
- 不替代现有的测试框架
- 不涉及代码审查流程

## Background & Context
- 原始VB代码是经过验证的可正常运行代码
- 现代码(Python)是从VB代码迁移/重构而来
- 之前发现过多次因未对比源代码导致的逻辑偏差问题
- 需要建立规范化的对比验证流程

## Functional Requirements
- **FR-1**: 修改数据处理或核心逻辑代码前，必须先阅读并理解对应模块的原始VB代码
- **FR-2**: 修改后必须进行行为对比验证，确保输出结果一致
- **FR-3**: 必须记录对比验证过程和结果
- **FR-4**: 验证不通过时，必须回退修改或重新分析

## Non-Functional Requirements
- **NFR-1**: 验证过程必须可追溯、可审查
- **NFR-2**: 对比验证必须覆盖所有核心数据处理逻辑
- **NFR-3**: 验证结果必须记录在案

## Constraints
- **Technical**: 原始代码为VB宏(.bas文件)，现代码为Python
- **Dependencies**: 需要同时访问原始VB代码和现代码

## Assumptions
- 原始VB代码是权威的行为参考
- 修改后的代码行为应与原始代码保持一致
- 开发人员可以阅读和理解VB代码

## Acceptance Criteria

### AC-1: 代码修改前的源代码阅读
- **Given**: 开发人员准备修改数据处理或核心逻辑代码
- **When**: 开始编写修改代码前
- **Then**: 必须先阅读对应的原始VB代码
- **Verification**: `human-judgment`
- **Notes**: 需要在修改记录中注明已阅读的源代码文件

### AC-2: 行为对比验证
- **Given**: 代码修改完成后
- **When**: 进行测试前
- **Then**: 必须使用相同输入数据对比现代码与原始代码的输出
- **Verification**: `programmatic`
- **Notes**: 对比必须覆盖正常情况和边界情况

### AC-3: 验证记录
- **Given**: 对比验证完成后
- **When**: 提交修改前
- **Then**: 必须记录验证过程、对比结果和差异分析
- **Verification**: `human-judgment`
- **Notes**: 记录应包括输入数据、输出对比、差异原因

### AC-4: 差异处理
- **Given**: 对比发现输出差异
- **When**: 验证过程中
- **Then**: 必须分析差异原因，确认是否为预期变更或bug
- **Verification**: `human-judgment`
- **Notes**: 非预期差异必须修复
